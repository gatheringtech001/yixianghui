### 2.2 架构设计原则



1. **解耦原则**：新增业务模块（G1-G4）通过依赖注入调用 RuoYi 核心模块（F1-F5），不修改 RuoYi 原生代码，降低框架升级成本；

2. **权限统一**：PC 后台与小程序共用后端接口，通过 RuoYi 权限模块（F1）控制数据访问（如顾问仅能查看分配的客户）；

3. **缓存策略**：高频访问数据（产品库存、字典数据、用户 Token）缓存至 Redis，订单创建用 Redis 分布式锁防超卖；

4. **异常处理**：复用 RuoYi 全局异常处理器（GlobalExceptionHandler），新增业务异常（如 StockInsufficientException）继承 RuoYi BizException，统一返回格式。

## 四、数据库设计（优化版：复用 + 新增）
本节对原有数据库设计进行规范化与优化，增强数据完整性、查询性能与可维护性，兼顾 MySQL 8.0 特性（CHECK、JSON、外键）与 RuoYi 复用约束。

注意事项摘要：
- 所有表使用 InnoDB 与 utf8mb4，主键建议使用 unsigned bigint，自增。
- 增加常用查询索引（user_id、status、create_time、product_id 等），必要时增加复合索引。
- 关键表增加乐观锁（version）或更新时间（update_time）以便并发控制。
- 库存 stock 使用 unsigned int 并结合 Redis 分布式库存与事务/乐观锁防超卖。
- 可选字段使用 JSON（如凭证图片）提高扩展性；保留兼容 varchar 的方案视运维要求选择。

#### 4.1 复用 RuoYi 核心表（无需修改，建议新增角色/字典数据）
- sys_user、sys_role、sys_dict_type、sys_dict_data 继续复用；新增 role_key 如 ADVISOR / CUSTOMER；新增字典类型如 ys_order_status、ys_product_status 等。

#### 4.3 字典与枚举建议
- 保留 sys_dict_data 存储业务枚举，避免硬编码；同时在应用层用常量映射，便于查询与展示。
- 建议字典项包含 code（tinyint/varchar）、label、sort、is_default 字段。

#### 4.4 其它优化与实施建议（简要）
- 库存：写路径使用数据库事务 + Redis 原子减库存（先预减 Redis，再入库确认）；下单失败回滚 Redis。并发高时使用分布式锁或基于库存流水的乐观方案。
- 索引：根据实际查询场景补充复合索引（如 product_id+status、user_id+status）。
- 审计与合规：如需保留删除记录，增加 deleted_flag 或单独历史表（ys_order_history、ys_product_history）。
- 数据迁移：上线前编写迁移脚本（Flyway/Liquibase 或手写 SQL），并在测试环境充分验证外键影响。
- 兼容性：若不允许外键约束（某些生产环境），在应用层保证参照完整性并保留索引。

## 五、核心接口设计（遵循 RuoYi 规范）

### 5.1 接口通用规范



* 统一前缀：PC 后台接口前缀`/business/`，小程序接口复用同一前缀（通过角色权限控制）；

* 请求方式：查询用`GET`，新增用`POST`，修改用`PUT`，删除用`DELETE`；

* 返回格式（复用 RuoYi Result 类）：



```
{

&#x20; "code": 200,       // 200成功，其他为错误码（如5001-参数缺失）

&#x20; "msg": "操作成功",  // 提示信息

&#x20; "data": {}         // 响应数据（列表页返回{total: 10, rows: \[]}）

}
```



* 认证方式：所有接口需在请求头携带`Authorization: Bearer {token}`（RuoYi 原生认证逻辑）。

## 六、核心业务流程设计

### 6.1 客户下单流程（小程序）




## 七、关键技术点与解决方案

### 7.1 防超卖解决方案



* 方案：Redis 分布式锁 + 数据库库存校验双重保障；

* 实现逻辑：

1. 订单创建时，用`RedisTemplate.opsForValue().setIfAbsent(productId, "LOCK", 30, TimeUnit.SECONDS)`抢占锁；

2. 锁抢占成功后，查询数据库库存（`SELECT stock FROM ys_product WHERE product_id=? FOR UPDATE`，行锁）；

3. 库存充足则扣减，不足则抛出`StockInsufficientException`；

4. 无论成功失败，最终通过`finally`释放锁（`RedisTemplate.delete(productId)`）。

### 7.2 小程序适配老人操作习惯



* 界面优化：字体大小≥16px，按钮高度≥48px，间距放大（避免误触）；

* 流程简化：下单流程≤3 步，关键操作（支付、提交）增加二次确认弹窗；

* 辅助功能：新增 “操作引导” 弹窗（首次进入功能页显示），支持字体放大切换。

### 7.3 数据权限控制（顾问仅看分配客户）



* 实现逻辑：复用 RuoYi 数据权限框架，在客户 / 订单查询 SQL 中动态拼接条件；

* 配置步骤：

1. 在`sys_role`表中，为 “康养顾问” 角色设置`data_scope=4`（自定义数据范围）；

2. 在 Mapper XML 中，通过 RuoYi 标签`${params.dataScope}`拼接条件：



```
SELECT \* FROM ys\_customer&#x20;

WHERE 1=1&#x20;

\${params.dataScope}  -- 动态拼接：AND customer\_id IN (SELECT customer\_id FROM ys\_advisor\_customer WHERE advisor\_id=#{currentUserId})
```

### 7.4 文件存储解决方案



* 产品封面图、售后凭证图片存储至阿里云 OSS；

* 实现：复用 RuoYi 文件上传组件，配置 OSS 访问密钥，上传后返回文件 URL 存入数据库；

* 权限控制：OSS 文件设置访问有效期（如 7 天），避免公开访问泄露。

## 4.6 新增区块
- **接口地址**: `POST /system/app_goods_related`
- **接口说明**: 新增区块
- **权限要求**: `system:app_goods_related:add`
- **请求参数**:
```json
  {
  "goodsId": "必填，商品ID",
  "sectionId": "必填，区块ID（英文唯一标识）",
  "sectionName": "必填，区块名称",
  "content": "必填，详情内容（HTML格式）",
  "sortOrder": 0,
  "minContentLength": 500
}
 ```
- **请求参数说明**:
  - sectionId: 区块唯一标识，建议使用英文，如：id_jibentese、id_canyin、id_jiaotong等
  - content: 支持HTML格式，用于前端渲染
  - minContentLength: 内容长度阈值，超过此长度前端显示展开/收起功能
- **响应数据**:
```json
  {
  "code": 200,
  "msg": "新增成功",
  "data": null
}
 ```
